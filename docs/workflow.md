# 开发过程与工作流说明

本项目由 Codex 在独立 main 仓库内从零逐阶段协作开发。应用运行模型是后端独立配置的 DeepSeek，开发工具、运行凭据和模型上下文完全分开；题目中的 Claude Code/DeepSeek 工具组合按用户确认作为示例，不虚构使用经历。本文 PDF 为一页，源文与完整过程记录一起保留。

## 实际流程

先阅读作业图片，区分题目要求、用户授权、实现建议与待确认项；将需求编号映射到验收。SDD 阶段先定义讨论状态、阵容/运行/消息/观点/事件归属、HTTP/SSE 契约和 SQLite 迁移，初始化锁定工程。DDD 按题目含义实施前端设计驱动：先集中模拟客户端做首页、阵容、演播厅和总结，在四种屏幕尺寸检查滚动与阅读位置；领域模块同时按职责划分。

TDD 以小批失败测试驱动生命周期、并发确认、事务回滚、自主意图与调度、冻结边界及总结恢复，先保存可复现失败，再实现、重构和提交。E2E 阶段连接真实 React、FastAPI、临时 SQLite 和 SSE，用可控模型替身验证完整业务、断线补发、双场隔离与重试。之后才接 DeepSeek 六任务，用真实输出和逐条引用复核内容质量；应用 Prompt 与开发任务原文分别保存，定向结果从不覆盖原场。

## 三个真实问题与解决路径

一是实时内容增长破坏历史阅读。仅看到页面初始布局不能证明演播厅可用；增加内部滚动、保留旧阅读位置和“有新内容”入口，浏览器检查普通、超宽、窄屏及持续增长，静态四尺寸与真实服务增长证据分别记录。

二是结构正确却出现假共识、条件扩大和漏提。模型可能把人设或单方提案当已发表的共同结论；补齐每条发言作者、回应目标与逐字来源，分草稿/逐项复核，保留前批观点作重新审核候选、收窄共同交集，并检查后续撤回。总结明确区分建议、共同主张及真正待澄清问题。程序守护身份、引用、版本和状态，语义判断另用实际模型输出核读，允许无证据时为空；保守召回仍非穷举。

三是思考模式的多步提取超过旧短预算，且供应商错误无法落入原数据库 CHECK。失败记录显示“单次 HTTP 超时”误约束整批草稿和复核；将每个 HTTP 的 120 秒与观点 240 秒/总结 180 秒总预算分开，追加006迁移支持安全供应商错误，不改旧校验和。先补失败用例再验证修复，余额补充后以清洁版本跑最终完整真实场：418.333秒、62次HTTP、8发言及4批观点，因验证次数上限结束；不把该上限当日常20条设置。

## 对工程化 AI 开发的理解

AI 适合在明确边界内加速规格、组件和测试实现，不能把流畅输出当事实或完成证据。有效协作是让每次任务有可审查输入、有限范围、失败用例和验收门槛；用数据库事务与版本守卫约束确定性规则，用真实内容复核处理语义风险。Git 保留演进，Prompt 原文与结果分开，未验证、限制和失败不被成功截图掩盖。最终交付再做干净目录锁定安装、初始化、样例与启动核对，避免“开发机能跑”成为唯一依据。远程发布与邮件发送需要后续用户操作，本文不宣称已提交作业。
