## PL-001 — 2026-10-08，需求分析与实施规划

类型：实际用户 Prompt；阶段：1，规格与规划准备。来源附件为图片，附件文字提取见 requirements，并非本条用户文本的一部分。

### Prompt 原文

```text
请基于附件要求，从零开发 AI Panel Studio：一个支持多专家实时圆桌讨论的本地 Web 应用。

应用运行时使用的模型服务后面通过后端独立配置。

本阶段完成需求分析与实施规划，暂不编写业务代码。

任务：
1. 提取功能要求、技术约束、交付材料及验收标准，为每项要求分配唯一编号。
2. 梳理创建讨论、生成嘉宾、确认阵容、观看讨论、查看总结的完整用户流程。
3. 明确 MVP 范围、讨论生命周期、异常状态和关键边界条件。
4. 评估技术方案，优先采用 React + TypeScript + Vite、FastAPI、SQLite、SSE、pytest 和 Playwright。
5. 制定覆盖 SDD、DDD、TDD、E2E 的分阶段实施计划，标明依赖关系和阶段验收条件。
6. 识别影响实现或交付的歧义，区分题目要求、实现建议和待确认事项。

产出：
- docs/requirements.md：需求与范围。
- docs/acceptance.md：验收矩阵。
- docs/plan.md：实施计划。
- docs/decisions.md：技术决策与待确认事项。
- AGENTS.md：项目约定。

项目约定：
- 保留现有文件和用户修改。
- 核心业务逻辑采用测试驱动开发。
- 按实际进展维护 docs/progress.md 和 docs/prompt-log.md。
- Prompt 原文与结果说明分别记录。
- 每阶段完成相关验证和 Git 提交。
- 已验证、未验证与存在限制的能力分别说明。

完成后报告主要设计决策、风险和下一阶段任务。
```

### 结果说明（与原文分开）

将附件拆为 48 条来源要求并关联验收，建立用户流程、生命周期、异常、技术决策、六阶段计划与项目约定；自主发言与实时共识分歧作为 MVP 核心保留。发现工具组合、DDD 含义、结束策略和最终提交时限等歧义，分别记录建议和待确认项，未生成业务代码。

## PL-003 — 2026-10-08至09，SDD 数据建模与工程初始化

类型：实际用户 Prompt；阶段：2，SDD规格与契约、工程基础。基础约束测试先失败后实现，尚不属于完整核心讨论引擎TDD阶段。

### Prompt 原文

```text
依据现有需求和验收矩阵，进入第二阶段：SDD 数据建模、接口契约与工程初始化。

设计任务：
1. 划分讨论管理、嘉宾生成、参与意图、发言调度、主持人控制、观点提取和事件分发模块。
2. 定义讨论、角色、角色状态、正式消息、共识分歧和事件的数据模型，明确关联关系及数据约束。
3. 设计讨论状态机，明确合法转换、启动幂等、结束条件及异常恢复。
4. 定义 HTTP API、错误格式和 SSE 事件契约，提供请求、响应及事件示例。
5. 明确数据库、运行任务、模型上下文和事件订阅的多讨论隔离机制。
6. 明确状态快照与事件订阅的衔接方式，处理重连、补发、排序和去重。

实现任务：
- 初始化前后端项目，锁定依赖版本，提供启动脚本。
- 建立 SQLite 初始化与迁移机制。
- 实现健康检查、配置读取、基础日志和统一错误处理。
- 定义统一模型调用接口、返回结果校验规则和确定性模拟实现。
- 提供 .env.example 和 README 初版。

沿用 React + TypeScript + Vite、FastAPI、SQLite 和 SSE 技术方案。模型服务配置后续提供，本阶段在 .env.example 中列明所需变量。密钥仅由后端环境变量读取，不进入前端、日志和接口响应。

产出：
- docs/architecture.md。
- docs/data-model.md，包含 ER 图。
- docs/api.md，包含请求响应及事件示例。
- 可启动的前后端工程和可初始化的数据库。

验收：
- 前后端能够启动，前端能够访问后端。
- 数据库初始化成功，重复执行行为明确。
- 接口和事件契约覆盖核心流程及异常情况。
- 数据格式与关键约束通过相应检查。

本阶段不展开完整讨论引擎，核心业务逻辑后续按 TDD 实现。普通实现参数采用合理默认值并记录决策。

更新项目约定中的当前阶段，沿用现有过程记录和 Git 提交要求。题目中的 Claude Code、DeepSeek 按工具示例处理，关闭对应待确认项。

完成后说明实际检查结果、未完成事项和下一阶段任务。
```

### 结果说明（与原文分开）

完成七模块边界、ER/字段约束、状态/幂等/异常恢复设计、HTTP/SSE机器契约和示例，建立锁定依赖的前后端、可重复迁移、基础接口及确定性模型协议。安装中遇到全局npm缓存权限/官方源延迟，改用项目缓存与本机可达镜像；检查发现参与意图角色与空阵容校验缺口，以两个实际失败测试补齐后通过；真实模型和讨论引擎仍待后续。

## PL-005 — 2026-10-09，阶段3 DDD前端设计

类型：实际用户Prompt；阶段：3，设计驱动页面与演播厅交互。浏览器用例验证前端模拟，不计为完整后端E2E或核心业务TDD。

### Prompt 原文

```text
进入第三阶段：DDD 前端页面与演播厅交互设计。依据现有需求、验收矩阵和已确定的 API/SSE 契约，完成可操作的前端流程。

页面任务：
1. 首页：展示进行中的讨论，支持新建和进入已有讨论，提供加载、空列表和失败状态。
2. 创建与阵容确认：输入话题和专家人数，默认 4 名专家；展示主持人与专家的姓名、职业/Title、立场和专属颜色，确认后进入演播厅。
3. 演播厅：展示讨论话题、主持人、专家独立状态卡、现场 Transcript、实时共识与分歧。
4. 结束状态：展示主持人的自然语言总结，并保留本场讨论内容供查看。

交互要求：
- 专家状态包含待机、准备发言、发言中及公开关注点，不展示隐藏推理。
- Transcript 显示姓名、职业/Title 和对应角色颜色，仅包含正式发言。
- 每次发言为 1—2 句，当前发言者有清晰的视觉提示。
- 共识与分歧在讨论过程中更新，不能只在结束时出现。
- 用户查看历史发言时保留阅读位置，并提示有新内容。
- 切换讨论时清理旧订阅和页面状态，避免混入上一场内容。
- 提供生成失败、连接中断及总结失败的页面状态和对应操作。

布局要求：
- 使用中文 UI，形成清晰的演播厅视觉层级。
- 页面保持视口高度，各内容区域独立滚动。
- 普通桌面合理划分嘉宾区、Transcript 和共识分歧区。
- 超宽屏控制文本阅读宽度；窄屏调整分区，保证所有内容可访问。
- 角色颜色、字体、间距和组件状态保持一致。

本阶段使用符合现有契约的模拟数据和事件完成交互，模拟逻辑集中管理，与页面组件分离，为后续接入真实后端保留替换位置。明确标识模拟模式，不将其描述为真实模型运行。

准备一场完整的模拟讨论，包含主持人开场、专家补充与反驳、讨论中的观点更新和最终总结。共识与分歧应有对应发言依据，不直接沿用仅凭主持人开场白生成共识的契约示例。

验收：
- 可以从首页完成创建、阵容确认、进入演播厅和查看总结的完整前端流程。
- 类型检查和生产构建通过。
- 使用浏览器实际检查 1366×768、1920×1080、2560×1080 和 390×844，验证布局、内部滚动、文字显示及主要操作。
- 为关键交互编写并运行必要的浏览器测试，明确这些是模拟数据下的前端验证。
- 保存关键页面截图，检查并修复溢出、遮挡和状态显示问题。

本阶段不实现后端讨论引擎或真实模型调用。更新验收矩阵、阶段约定和过程记录，完成 Git 提交。

完成后提供本地预览方式、页面截图、实际检查结果及未完成事项。
```

### 结果说明（与原文分开）

建立首页至总结的中文前端模拟闭环，使用独立mock客户端和公开事件投影，支持引用专家发言的共识/分歧、上翻保留位置、切换清理、模拟断线及阵容/总结失败重试。四种尺寸实机浏览器检查后收紧低高度桌面布局，并修正两专家角色版本、话题标点句数和生成刷新恢复；具体最终命令结果见progress，后端引擎及真实模型继续留待后续。
