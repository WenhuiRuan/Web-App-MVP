## PL-006 — 2026-10-09，阶段4第一批TDD后端生命周期

类型：实际用户Prompt；阶段4 TDD。要求每小批先运行失败测试，再实现与重构；本批保留前端模拟模式。

### Prompt 原文

```text
进入第四阶段，按 TDD 实现后端核心逻辑。先完成第一批：讨论生命周期、嘉宾生成和持久化。

沿用现有数据模型、API 契约和 ModelGateway。先编写并运行失败测试，再实现对应逻辑，按小批次完成测试、实现和重构。

测试与实现范围：

1. 创建讨论：校验话题和专家人数，默认 4 名专家，保存到 SQLite。
2. 查询讨论列表与快照：按讨论归属读取数据，状态过滤和排序符合契约。
3. 生成嘉宾：通过后台任务调用 ModelGateway，校验主持人、专家数量、必要字段及角色归属，成功后保存完整阵容。

5. 异常处理：生成超时、非法输出及任务失败有明确状态，保留话题并支持约定的重试。
6. 持久化事件：业务数据与对应事件在同一事务中提交，失败时整体回滚。

实现已定义的创建、列表、快照、嘉宾生成、启动及操作查询接口。使用后端确定性模拟模型执行任务，不复用前端台本作为后端业务实现。

后台任务由应用统一管理，处理重复提交、异常和服务关闭。启动接口先完成运行实例及状态的建立，自动发言调度在下一批实现。

验收：

- 使用真实 FastAPI 和 SQLite 完成创建、生成阵容、确认启动的接口流程。
- 测试默认人数、非法输入、模型异常、失败重试和非法状态转换。
- 测试同一请求重复提交、不同请求同时确认，确保只有一个运行实例。
- 同时处理两个讨论，确认数据与任务结果互不串场。
- 重启服务后已提交数据仍可查询，未完成任务有明确状态。
- 写入失败不留下部分阵容或成功事件。
- 现有基础测试、契约检查和前端构建继续通过。

本批不修改演播厅布局，前端仍保留模拟模式。真实模型配置后续提供。

同步修正 progress.md 中第三阶段的状态，更新本阶段约定、验收记录和实际 Prompt 记录，按实现批次提交 Git。
```

## PL-007 — 2026-10-09，阶段4第二批自主调度与主持控制

类型：实际用户Prompt；阶段4 TDD。

### Prompt 原文

```text
继续第四阶段第二批，按 TDD 实现自主发言调度与主持人控制。

沿用现有运行实例、SQLite 事务、持久化事件和任务监督器。按小批次先编写失败测试，再实现和重构。

实现任务：
1. 启动成功后，由后台任务推进讨论。同一运行实例只能有一个讨论任务，重复启动不重复调度。
2. 主持人先开场；专家根据当前 Transcript 判断是否参与，返回举手、抢答、补充、反驳或暂不发言的意图。
3. 校验参与者、回应目标和上下文归属，再根据相关性、回应关系及近期发言情况选择发言者。避免固定轮流和单人持续占用。
4. 没有有效参与意图时，由主持人追问；讨论推进过程中支持主持人串联和收束。
5. 发言生成应携带本次参与类型和回应目标，主持人发言应携带开场、追问或串联等任务信息。必要时补充模型请求字段，同步契约、示例和校验。
6. 每次正式发言控制为 1—2 句，保存消息并发布持久化事件。专家状态按实际任务更新为待机、准备发言和发言中。
7. 达到发言次数、运行时长上限，或主持人决定结束时，停止新增发言，进入 SUMMARIZING，并固定总结对应的消息边界。观点提取和最终总结在下一批完成。

数据与任务要求：
- 模型调用在数据库事务之外执行。
- 正式消息、角色状态及对应事件按明确的事务边界保存。
- 拒绝重复提交、过期轮次及中断运行的迟到结果。
- 多场讨论独立推进，一场失败不影响另一场。
- 模型超时、非法输出和任务异常有明确处理，重试次数有限。
- 只保存参与意图和公开关注点，不索取或展示隐藏推理。

重点测试：
- 不同有效意图产生对应的调度结果，覆盖同时申请、补充、反驳、无人参与和连续占用。
- 发言请求正确传递参与类型、回应目标及主持任务。
- 同一场只有一个公开发言者，消息顺序连续且不重复。
- 非法回应、超长发言、写入失败及迟到结果不会破坏已提交数据。
- 重复启动只产生一个讨论任务。
- 两场讨论交错推进，任务、消息和事件互不串场。
- 结束条件生效，进入 SUMMARIZING 后不再新增发言。
```
