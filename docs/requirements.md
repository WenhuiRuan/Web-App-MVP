## 2. 产品目标与用户

AI Panel Studio 是本地运行的多专家 AI 圆桌讨论 Web 应用。用户输入议题并指定专家数，确认主持人及专家阵容后观看有主持、有争辩、有实时共识分歧的讨论，最终获得自然语言总结。

知识工作者/研究人员需要多角度分析和争辩摘要；产品/决策人员需要发现盲点、检验假设；教育/内容创作者需要结构清晰、具有叙事感的讨论素材。产品应缓解单一视角、上下文割裂、讨论过程不可见、多议题管理混乱。附件用户画像中的“可录制、可回放”属于使用愿景，具体功能未列为硬性需求，见 Q-06。

## 6. MVP 与范围外

MVP 纳入 F-01～F-15 与 T-01～T-07；包含持久化回看已保存的讨论内容、可见失败状态、连接恢复及最小恢复操作。这些可靠性补充是 R 来源，不能删减题目中的并行讨论、自主发言或实时提炼。

暂不纳入账号权限、公开互联网部署、多人协作输入、人工参加辩论、语音/视频、音视频录制、按时间轴重放、知识库/网页检索、可视化供应商设置页、复杂角色编辑、主动推送和分布式任务队列。用户可返回首页或关闭页面，后端讨论继续；“观看”不表示视频直播。历史文本可查不等于时间轴回放。更换整套嘉宾、手动结束是建议项，需 Q-05 冻结后进入契约。

## 7. 完整用户流程

| 步骤 | 用户动作与页面 | 后端行为及可见结果 | 失败与返回路径 |
|---|---|---|---|
| 1 | 首页查看进行中议题；选择新建或旁观 | 列表含当前生命周期、专家数量；旁观读快照再订阅 | 列表失败可重试；目标不存在明确提示 |
| 2 | 输入议题、专家数，点击生成 | 校验成功保存讨论，进入生成中，按钮避免重复提交 | 不合法不调用模型；服务未配置展示配置错误而非假成功 |
| 3 | 等待并审阅主持人/专家卡片 | 后端模型生成、结构校验；完整阵容进入待确认 | 不完整/超时保留议题，显示失败及重试入口，不自动开始 |
| 4 | 确认阵容 | 冻结 roster_revision；幂等开始命令只启动一个运行实例 | 过期阵容返回冲突并重新加载；重复点击返回已有运行 |
| 5 | 进入演播厅观看 | 主持人开场；专家状态、公开关注点、1–2 句发言、共识分歧持续更新 | 断线提示重连；切换议题释放旧订阅；不串数据 |
| 6 | 讨论达到结束策略 | 停止调度新专家发言，主持人生成自然语言总结 | 总结失败保留 transcript，可单独重试总结 |
| 7 | 阅读总结并返回列表/回看 | 显示结论、主要共识、关键分歧与局限；重开读取保存结果 | 无完整总结明确标为失败/待重试，不伪造已完成 |

建议演播厅：顶部议题和状态，中部嘉宾小窗、公开 transcript、共识分歧面板。窄屏改为选项卡/可切换面板，保证当前区域内部滚动，键盘能到达所有区域；保持嘉宾颜色一致并辅以姓名文字。用户正在读历史发言时不强制跳到底部，提供新发言提示。

## 8. 讨论生命周期（R，实施前冻结）

| 状态 | 含义 | 合法迁移及条件 |
|---|---|---|
| DRAFT | 已保存议题，尚未生成 | 提交生成 → GENERATING |
| GENERATING | 生成并验证阵容 | 合法完整阵容 → READY；失败 → FAILED(stage=roster) |
| READY | 待用户确认 | 确认当前 revision → RUNNING；若批准重生成 → GENERATING |
| RUNNING | 开场、申请发言、仲裁、公开发言、提炼 | 达到结束策略 → SUMMARIZING；不可恢复错误 → FAILED(stage=discussion) |
| SUMMARIZING | 冻结公开发言边界并生成总结 | 持久化合格总结 → COMPLETED；失败 → FAILED(stage=summary) |
| COMPLETED | 完成且只读 | 不继续发言；新讨论使用新 ID |
| FAILED | 可见的阶段失败，保留已提交数据 | 阵容失败可重试 → GENERATING；总结失败可重试 → SUMMARIZING；讨论失败本 MVP 建议只读并另建讨论 |
| INTERRUPTED | 后端进程意外停止造成中断 | 重启将遗留进行中状态标为中断；生成/总结可按相应阶段重试，讨论中断不自动续跑 |

连接状态另设 connecting/live/reconnecting/offline，与讨论生命周期正交；浏览器断开不把讨论标为 FAILED。专家小窗状态与讨论状态分离，一场讨论最多一位公开发言者；可同时有多人准备发言。完成后清除“发言中”。

建议结束策略：主持人判断讨论覆盖充分，或达到最大公开发言数/运行时长/预算上限。默认值见 Q-03；到达上限先进入总结，给总结保留预算。上游不可用导致无法总结则如实失败。无候选专家时主持人追问或选择合法结束，不按固定次序强行轮流。

## 9. 异常与边界（R，验收矩阵列为建议基线）

| 场景 | 必须明确的处理 |
|---|---|
| 空白/超长议题、非整数/越界人数 | 前后端一致校验，不发起模型调用；建议议题 1–500 个 Unicode 码点、专家 2–6，默认 4，均待 Q-02 |
| 双击生成/确认，多标签操作 | 命令幂等键、roster_revision 和 run_id 限制，不能产生两个主持人流程 |
| 模型格式错误、少人、多句、空输出 | 后端结构和内容校验，最多一次修复尝试（建议）；仍失败则显式失败，不显示 JSON 或虚假状态 |
| 鉴权失败、限流、超时、网络断开 | 401/403 不盲重试；429/暂时性故障有限退避；记录脱敏错误分类，前端保留已有结果 |
| 同时举手、长期无人发言/独占发言 | 依据意图关联度、回应目标、等待时间及近期占用仲裁；模型申请与可测的调度规则分离 |
| 共识不足、提炼错误 | 允许空共识和未解决分歧；更新须引用已有 turn_id，不能为了填满面板制造一致意见 |
| 刷新/断线/乱序/重复事件 | 快照带事件游标，补传游标后的事件；客户端去重；缺口重新获取快照 |
| 进程崩溃 | 未提交发言不视为完成，已提交内容可读；重启标中断，不自动重复付费调用 |
| 同时推进多个讨论 | 状态、事件序号、幂等键、上下文和模型请求归属按 discussion_id 隔离；全局并发限制不应导致单议题饿死 |
| 长讨论/上下文上限 | 使用公开滚动摘要与最近发言构建上下文，保留原始 transcript；摘要来源和模型预算可追踪 |
| 恶意议题或模型 HTML/JSON | 作为不可信数据处理，默认纯文本渲染；公开摘要必须是专门生成的可公开文本，不收集隐藏推理 |
| SQLite 忙、磁盘满、提交失败 | 短事务/有界重试；未持久化不广播“已完成”；用户看到错误，不丢失先前提交内容 |
| 页面关闭/后台/切换议题 | 关闭订阅但不取消讨论；新标签从保存快照恢复；不持有旧议题渲染状态 |

## 10. 成功判定与当前限制

成功不仅是 API 返回：完整用户闭环、实时感、自主交锋、公开内容合规、并行隔离、可追溯交付必须同时满足。内容质量需人工复核：身份视角有区别，发言回应已有观点而非各说各话，共识分歧有出处，总结不加入无依据事实。

当前完整前后端、SQLite/SSE及六任务DeepSeek已实现并完成有限真实质量验收；本地交付见delivery。单worker/跨平台/真实并发与p95限制见README，语义质量不穷举；前文阶段范围按当时授权保留。
