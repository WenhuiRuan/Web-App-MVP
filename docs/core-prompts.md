## 3 DDD 前端设计与页面实现

记录编号：PL-005

我先用集中模拟客户端完成页面和演播厅，再接后端。内容增长时暴露了滚动和阅读位置问题，随后用浏览器检查并修正。

```text
进入第三阶段：DDD 前端页面与演播厅交互设计。依据现有需求、验收矩阵和已确定的 API/SSE 契约，完成可操作的前端流程。

页面任务：
1. 首页：展示进行中的讨论，支持新建和进入已有讨论，提供加载、空列表和失败状态。
2. 创建与阵容确认：输入话题和专家人数，默认 4 名专家；展示主持人与专家的姓名、职业/Title、立场和专属颜色，确认后进入演播厅。
3. 演播厅：展示讨论话题、主持人、专家独立状态卡、现场 Transcript、实时共识与分歧。
4. 结束状态：展示主持人的自然语言总结，并保留本场讨论内容供查看。

交互要求：
- 专家状态包含待机、准备发言、发言中及公开关注点，不展示隐藏推理。
- Transcript 显示姓名、职业/Title 和对应角色颜色，仅包含正式发言。
- 每次发言为 1—2 句，当前发言者有清晰的视觉提示。
- 共识与分歧在讨论过程中更新，不能只在结束时出现。
- 用户查看历史发言时保留阅读位置，并提示有新内容。
- 切换讨论时清理旧订阅和页面状态，避免混入上一场内容。
- 提供生成失败、连接中断及总结失败的页面状态和对应操作。

布局要求：
- 使用中文 UI，形成清晰的演播厅视觉层级。
- 页面保持视口高度，各内容区域独立滚动。
- 普通桌面合理划分嘉宾区、Transcript 和共识分歧区。
- 超宽屏控制文本阅读宽度；窄屏调整分区，保证所有内容可访问。
- 角色颜色、字体、间距和组件状态保持一致。

本阶段使用符合现有契约的模拟数据和事件完成交互，模拟逻辑集中管理，与页面组件分离，为后续接入真实后端保留替换位置。明确标识模拟模式，不将其描述为真实模型运行。

准备一场完整的模拟讨论，包含主持人开场、专家补充与反驳、讨论中的观点更新和最终总结。共识与分歧应有对应发言依据，不直接沿用仅凭主持人开场白生成共识的契约示例。

验收：
- 可以从首页完成创建、阵容确认、进入演播厅和查看总结的完整前端流程。
- 类型检查和生产构建通过。
- 使用浏览器实际检查 1366×768、1920×1080、2560×1080 和 390×844，验证布局、内部滚动、文字显示及主要操作。
- 为关键交互编写并运行必要的浏览器测试，明确这些是模拟数据下的前端验证。
- 保存关键页面截图，检查并修复溢出、遮挡和状态显示问题。

本阶段不实现后端讨论引擎或真实模型调用。更新验收矩阵、阶段约定和过程记录，完成 Git 提交。

完成后提供本地预览方式、页面截图、实际检查结果及未完成事项。
```

## 4 TDD 生命周期与阵容

记录编号：PL-006

这一批先写生命周期、并发确认和事务失败用例，再实现业务。通过唯一运行记录、幂等命令和任务监督，处理重复启动及中断。

```text
进入第四阶段，按 TDD 实现后端核心逻辑。先完成第一批：讨论生命周期、嘉宾生成和持久化。

沿用现有数据模型、API 契约和 ModelGateway。先编写并运行失败测试，再实现对应逻辑，按小批次完成测试、实现和重构。

测试与实现范围：

1. 创建讨论：校验话题和专家人数，默认 4 名专家，保存到 SQLite。
2. 查询讨论列表与快照：按讨论归属读取数据，状态过滤和排序符合契约。
3. 生成嘉宾：通过后台任务调用 ModelGateway，校验主持人、专家数量、必要字段及角色归属，成功后保存完整阵容。
4. 确认阵容与启动：确认前不可运行，过期阵容不可启动，重复请求及并发确认只能产生一个运行实例。
5. 异常处理：生成超时、非法输出及任务失败有明确状态，保留话题并支持约定的重试。
6. 持久化事件：业务数据与对应事件在同一事务中提交，失败时整体回滚。
7. 数据隔离：不同讨论的阵容、运行实例、操作记录和事件不能相互引用或覆盖。

实现已定义的创建、列表、快照、嘉宾生成、启动及操作查询接口。使用后端确定性模拟模型执行任务，不复用前端台本作为后端业务实现。

后台任务由应用统一管理，处理重复提交、异常和服务关闭。启动接口先完成运行实例及状态的建立，自动发言调度在下一批实现。

验收：

- 使用真实 FastAPI 和 SQLite 完成创建、生成阵容、确认启动的接口流程。
- 测试默认人数、非法输入、模型异常、失败重试和非法状态转换。
- 测试同一请求重复提交、不同请求同时确认，确保只有一个运行实例。
- 同时处理两个讨论，确认数据与任务结果互不串场。
- 重启服务后已提交数据仍可查询，未完成任务有明确状态。
- 写入失败不留下部分阵容或成功事件。
- 现有基础测试、契约检查和前端构建继续通过。

本批不修改演播厅布局，前端仍保留模拟模式。真实模型配置后续提供。

同步修正 progress.md 中第三阶段的状态，更新本阶段约定、验收记录和实际 Prompt 记录，按实现批次提交 Git。

完成后说明接口实际运行结果、测试覆盖及未完成事项，下一批继续自主发言调度和主持人控制。
```

## 5 TDD 观点提取与主持总结

记录编号：PL-008

这一批把观点提取、总结和恢复分开实现，重点核对来源、版本和冻结的消息范围。取消后仍返回的模型结果可能造成迟到提交，因此增加了领取和状态检查。

```text
继续第四阶段第三批，完成讨论过程中的共识、分歧提取和主持人最终总结。沿用现有讨论引擎、模型接口、SQLite 事务和持久化事件。

先梳理现有契约与实现的缺口，按观点提取、总结完成、失败恢复三个小批采用 TDD 推进。

一、实时观点提取

1. 根据已提交的正式发言持续提取共识与分歧，在讨论进行期间更新，不能只在结束后生成。
2. 每项观点引用具体来源消息。引用必须属于当前讨论和运行，且不超过本次提取的消息边界。
3. 区分共同认可的观点与尚未解决的分歧，证据不足时允许为空，不能把单人的意见直接写成共识。
4. 明确提取触发时机、版本和更新方式，拒绝重复提交及旧结果覆盖新结果。
5. 将观点与对应事件原子保存，快照能够返回最新内容。
6. 提取任务采用有限超时与重试；失败时保留已有观点，并明确后续处理，不让讨论无限等待。

二、主持人最终总结

1. 进入 SUMMARIZING 后，依据已冻结的消息边界生成主持人总结，不再增加普通讨论发言。
2. 总结使用可读的自然语言，概括主要观点、已有共识和未解决分歧。原始 JSON 不作为总结正文。
3. 总结任务使用独立的有限预算，确保讨论因时长上限结束后仍可生成总结。
4. 总结、对应事件和 COMPLETED 状态按明确的事务边界提交，不能出现没有总结却已完成的状态。
5. 实现总结失败和中断后的重试。重试沿用原讨论与消息边界，不重新生成阵容或重放讨论。
6. 并发或重复重试只产生一个有效任务，迟到结果不能覆盖已完成的总结。

三、重点验证

- 使用可控模型替身，验证讨论结束前出现至少两次有效观点更新。
- 覆盖无充分共识、非法来源、跨讨论引用和旧版本提交。
- 覆盖主持结束、次数上限和时长上限后的总结生成。
- 覆盖总结超时、非法输出、事务写入失败及重试成功。
- 验证重复请求不产生重复总结，重启保留消息与已提交观点。
- 验证两场讨论交错推进，观点、总结和失败状态互不影响。

本批通过真实 FastAPI 和 SQLite 验证新增流程。SSE、前端业务接入和真实模型验证留在后续阶段。

测试聚焦新增功能及受影响的回归用例。已有且未受影响的测试结果沿用，不重复执行布局和截图检查。

更新数据模型、API、架构、验收矩阵、进展和 Prompt 记录，按实际完成的小批提交 Git。

完成后报告观点更新的实际时机、总结及重试流程、验证结果和剩余事项。
```

## 6 E2E 前后端联调

记录编号：PL-009

我用真实前后端、临时 SQLite 和可控模型替身验证 HTTP/SSE 闭环。断线补发、双场隔离和总结重试分别保留证据，之后再单独验证真实模型内容。

```text
进入第五阶段，接通 SSE 和前端业务流程，并完成真实前后端的浏览器 E2E。沿用现有页面、讨论引擎和数据库，按 SSE、前端接入、E2E 三个小批推进。

一、实现 SSE

1. 挂载讨论事件接口，从已提交的持久化事件读取并发送，保持每场讨论的事件顺序。
2. 按现有契约处理 after 和 Last-Event-ID，校验讨论归属及游标范围。
3. 衔接快照与事件订阅，保证订阅建立期间产生的事件能够补发。
4. 实现心跳、断线重连和连接清理。观察者断开不能停止后端讨论，等待事件期间不能长期占用数据库事务。
5. 先写关键失败测试，覆盖补发、游标异常、跨讨论订阅、断线恢复及终态关闭。

二、接入前端业务流程

1. 实现真实 HTTP/SSE 客户端，通过统一入口提供给页面和 hooks，保留模拟客户端用于独立测试。
2. 接通首页列表、创建讨论、生成嘉宾、确认阵容、进入演播厅、查看总结和总结重试。
3. 同步前后端类型，补齐 insight_status、failure_code 等新增字段，调整事件投影和错误显示。
4. 页面能够实时展示角色状态、公开关注点、正式发言、共识分歧和总结。内部参与意图不进入 Transcript。
5. 处理重复事件、事件缺口、旧连接回调及讨论切换；需要恢复时重新获取快照并续订。
6. 明确观点提取失败状态如何同步到页面，保留已有观点，不能把失败显示为空结果。
7. 刷新或中途加入时，从后端恢复已有内容。总结重试成功后及时更新页面，不重放讨论。
8. 更新页面中与当前实现不符的模拟说明，准确显示当前模型模式。

三、完成浏览器 E2E

使用真实前端、FastAPI、临时 SQLite 和可控后端模型替身。业务 HTTP 和 SSE 请求必须经过实际服务。

重点覆盖：
- 创建讨论、查看阵容、确认启动、持续发言、实时观点更新和最终总结的完整流程。
- 首页进入正在进行的讨论，以及刷新后恢复内容。
- 断线期间后端继续推进，重连后消息完整且不重复。
- 总结失败后在页面重试，原消息和观点保持不变。
- 两场讨论同时推进，页面状态、消息、观点和事件互不串场。
- Transcript 的姓名、职业和颜色一致；角色窗口不展示隐藏推理；总结不显示原始 JSON。
- 真实内容持续增长时，页面无整体溢出，各区域独立滚动，普通、超宽和窄屏下主要操作可用。
- 浏览器响应与前端构建产物不包含后端密钥。

复用已有测试和验证记录，新增本阶段场景，运行受影响的回归。未变化的后端规则和静态布局检查不重复执行。

本阶段继续使用后端模型替身，真实模型适配与内容质量验证留在下一阶段。

更新 API、架构、验收矩阵、README、进展和 Prompt 记录，按实际完成的小批提交 Git。

完成后报告实际接通的用户流程、SSE 恢复行为、E2E 结果、发现并修复的问题及剩余事项。
```
